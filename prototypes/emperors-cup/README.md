## 試作の扱いと制限

- 対象はブレックスのファイナルラウンド。中立会場としてhはnull。表の掲載順をホーム扱いしない。
- 固定IDは大会年度＋ラウンド＋公式schedulekey。日付、相手、配列位置をIDに使わない。
- 未確定の相手は除外。最終スコアは「試合終了」の場合だけ取得。空ページ・重複ID・不正スコアはエラーとして停止する。
- 年月と取得元URLの年度を照合する。前回ページを今季として指定すると停止する。ただし入力HTMLそのものの出所を認証する仕組みではない。本番ではURLと取得本文を同じ取得処理で結び付け、見出しの大会名も確認する必要がある。
- 今季の開催日、ラウンド名、延期・中止、IDのない未開催カード、公式サイトの構造変更への対応は未実装。
- 既存のマーク・メモ・追加試合の移行、本番への書き込み、画面表示、定期実行は未実装。

## 本番化の案

1. 今季の公式カードが公開された段階で取得元とIDの安定性を再確認。ブレックス公式の日程ページも補助候補として調査する。

3. 画面は専用IDで試合を読み込み、マーク・メモも専用IDで保存する。data.jsの配列位置と既存mk()のキーは変更しない。スコアも同じIDに紐付ける。
4. 新規・変更・終了件数を保存前に検証し、日程変更、重複、取得失敗、中止、再取得を検証する。既存の追加試合との重複扱いも決める。
